## A. 读懂 DDL

**题 1**　`SHOW CREATE TABLE sku`，找出并说明：主键是哪列、唯一键是哪列、有哪些普通索引、字符集是什么。
- 自测：能对应上 `PRIMARY KEY(id)`、`uk_sku_code`、`idx_spu_id`、`utf8mb4`。

**题 2**　`sku.price` 是什么类型？为什么电商金额**必须**用它、不能用 `FLOAT`/`DOUBLE`？
- 提示：`DECIMAL(10,2)` 是定点数；浮点是二进制近似，`0.1+0.2 != 0.3`。
- 自测（亲手看浮点误差）：
  ```sql
  SELECT 0.1 + 0.2 = 0.3 AS 用字面量;          -- 定点，通常为 1
  SELECT CAST(0.1 AS DOUBLE) + CAST(0.2 AS DOUBLE) = 0.3 AS 用double;  -- 浮点，可能为 0
  ```

**题 3**　`spu.id` 是 `BIGINT UNSIGNED AUTO_INCREMENT`。回答：
- 为什么用 `BIGINT` 不用 `INT`？（`INT UNSIGNED` 上限约 42 亿，大电商会不够）
- `UNSIGNED` 省了什么？（不要负数，范围翻倍）
- 为什么自增主键对聚簇索引友好？（顺序插入、页分裂少，复习 M02-02）

## B. 类型选型判断

**题 4**　下面每个字段，你会选什么 MySQL 类型？说理由：
1. 商品状态（上架/下架/预售，最多十来种）
2. 手机号
3. 用户余额（金额）
4. 商品详情富文本（可能几千字）
5. 下单时间
6. 是否删除标记
- 提示：状态用 `TINYINT`+应用枚举（不用 MySQL `ENUM`，为什么？）；手机号用 `VARCHAR` 不用 `BIGINT`（前导 0、不做运算）；富文本 `TEXT`；时间 `DATETIME`；金额 `DECIMAL`。

**题 5**　`VARCHAR(50)` 和 `CHAR(50)` 的区别？分类名 `name` 为什么 `VARCHAR` 不 `CHAR`？
- 提示：`CHAR` 定长补空格、适合长度固定的（如国家码）；`VARCHAR` 变长省空间、适合长度不定的。

**题 6（动手）**　`created_at` 用了 `DATETIME` + `DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP`。写一条 `UPDATE` 改某行的 `name`，观察 `updated_at` 有没有自动变、`created_at` 有没有变。
- 自测：`updated_at` 应自动刷新，`created_at` 不动。
- 想清楚：`DATETIME` 和 `TIMESTAMP` 的区别（范围、2038 问题、时区行为）。

## C. 约束与完整性

**题 7（动手，故意触发错误理解约束）**　尝试插入一条 `sku_code` 和现有重复的 SKU，观察报什么错。
- 提示：`uk_sku_code` 唯一键会拦，报 `Duplicate entry ... for key 'uk_sku_code'`。
- 意义：唯一键在数据库层兜底"业务唯一"，不完全靠应用判重。

**题 8**　`sku.stock` 是 `INT UNSIGNED`。尝试 `UPDATE sku SET stock = stock - 1000 WHERE id=7`（id=7 库存只有 10），会发生什么？
- 提示：`UNSIGNED` 不允许负数，会报 `Out of range` 错误（严格模式下）。
- 想清楚：这能不能当"防止超卖"的手段？为什么光靠它不够（并发下的竞态，M03/M11 讲）？

**题 9**　商品域为什么用**逻辑外键**（不写 `FOREIGN KEY`）？物理外键的代价是什么？（复习 M02-01 决策 4）
- 动手验证逻辑外键"不兜底"：给 `sku` 插一条 `spu_id=999999`（不存在的 SPU），看数据库拦不拦。
- 期望：**能插进去**（数据库不校验），说明引用完整性要应用层保证。

## D. 范式 / 反范式 / SPU-SKU

**题 10**　为什么价格、库存放在 `sku` 而不是 `spu`？如果放 `spu` 会导致什么表达不出来？
- 提示：同一商品不同规格不同价/不同库存（256G vs 512G）。

**题 11**　`category` 用邻接表（`id + parent_id`）。写一条 SQL：查"手机"(id=2) 的**直接子分类**。
- 提示：`WHERE parent_id = 2`。
- 进阶：查"手机数码"(id=1) 的**所有后代分类**（递归）。用 `WITH RECURSIVE`：
  ```sql
  WITH RECURSIVE sub AS (
    SELECT id, parent_id, name FROM category WHERE id = 1
    UNION ALL
    SELECT c.id, c.parent_id, c.name FROM category c JOIN sub ON c.parent_id = sub.id
  )
  SELECT * FROM sub;
  ```
  自己跑一遍，理解递归 CTE 怎么一层层往下找。

**题 12**　`sku.spec_json` 用了 JSON 列存销售属性。写 SQL 查出"容量为 256G"的所有 SKU。
- 提示：`WHERE spec_json->>'$.容量' = '256G'`（`->>` 取值并去引号）。
- 想清楚：JSON 列的**代价**是什么？（不好建索引、不好精确筛选统计）什么时候该改成独立规格表？（复习 M02-01 决策 3）

**题 13（设计题，纸上）**　如果现在要支持"按颜色/容量筛选商品"（像京东左侧筛选栏），当前 JSON 方案够用吗？你会怎么改模型？代价是什么？
