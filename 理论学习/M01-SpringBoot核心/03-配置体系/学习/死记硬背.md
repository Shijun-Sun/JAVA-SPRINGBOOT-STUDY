# M01-03 · 配置体系死记硬背

> 这份只放高频结论。原理和边界以[主讲义](./03-配置体系.md)为准。

## 一、必须背

### 1. 外部化配置的目标

> 同一份构建产物，通过不同运行环境提供配置，而不是为每个环境重新编译一份包。

### 2. 常用配置优先级（低 → 高）

```text
JAR 内 application.yml
< JAR 内 application-{profile}.yml
< JAR 外 application.yml
< JAR 外 application-{profile}.yml
< 环境变量
< Java 系统属性 -Dkey=value
< 命令行参数 --key=value
```

同名属性由高优先级来源覆盖。

### 3. Profile

```bash
java -jar app.jar --spring.profiles.active=dev
SPRING_PROFILES_ACTIVE=prod java -jar app.jar
```

- `application.yml`：公共、安全默认值；
- `application-dev.yml`：只写 dev 差异；
- `application-prod.yml`：只写 prod 差异；
- 没有显式 Profile 时使用 `default`；
- 多个 Profile 冲突时通常后者获胜；
- `spring.profiles.active/include/group` 只能放在非 Profile 专用文档。

### 4. `@Value` 与 `@ConfigurationProperties`

| 场景 | 选择 |
|---|---|
| 一两个独立简单值 | `@Value` |
| 同一前缀下的一组配置 | `@ConfigurationProperties` |
| 嵌套对象、集合、类型转换、校验 | `@ConfigurationProperties` |

配置类必须通过以下方式之一注册：

```java
@ConfigurationPropertiesScan
```

或：

```java
@EnableConfigurationProperties(ProductProperties.class)
```

### 5. 命名规则

文件里推荐 kebab-case：

```text
product.pricing.max-page-size
```

对应 Java：

```text
maxPageSize
```

环境变量转换：

1. `.` → `_`；
2. 删除 `-`；
3. 转大写。

```text
product.pricing.max-page-size
→ PRODUCT_PRICING_MAXPAGESIZE
```

### 6. 占位符

```yaml
endpoint: "${PRODUCT_STORAGE_ENDPOINT:http://localhost:9000}"
```

- 冒号后是默认值；
- 密码、Token、AccessKey 不应提供仓库内弱默认值；
- 严重配置缺失应在启动阶段失败。

### 7. 校验

```java
@Validated
@ConfigurationProperties("product")
public record ProductProperties(
        @NotBlank String displayName,
        @Valid @NotNull Storage storage
) {}
```

- 根配置：`@Validated`；
- 嵌套对象：`@Valid`；
- 缺失/非法：让应用启动失败，不要拖到请求阶段。

### 8. Secret 边界

- 不提交真实密码、Token、AccessKey、私钥；
- 不打印完整配置对象；
- 不通过接口返回 Secret；
- 不公开 Actuator `env` / `configprops`；
- `ENC(...)` 不是 Spring Boot 原生通用解密协议；
- 密文与解密密钥在同一仓库不构成有效安全边界；
- 泄露后必须轮换凭据。

## 二、必须会写

### YAML 层级配置

```yaml
product:
  pricing:
    currency: CNY
    max-page-size: 100
    cache-ttl: 30s
  storage:
    endpoint: http://localhost:9000
    allowed-types:
      - jpg
      - png
```

### 不可变配置对象

```java
@Validated
@ConfigurationProperties(prefix = "product")
public record ProductProperties(
        @NotBlank String displayName,
        @Valid @NotNull Pricing pricing
) {
    public record Pricing(
            @NotBlank String currency,
            @Min(1) int maxPageSize,
            @NotNull Duration cacheTtl
    ) {}
}
```

### Profile 激活

```bash
./mvnw spring-boot:run -Dspring-boot.run.profiles=dev
```

打包后：

```bash
java -jar target/product-service-0.0.1-SNAPSHOT.jar \
  --spring.profiles.active=prod
```

### 覆盖配置

```bash
PRODUCT_PRICING_CURRENCY=USD java -jar app.jar
java -Dproduct.pricing.currency=EUR -jar app.jar
java -jar app.jar --product.pricing.currency=JPY
```

## 三、必须会排错

“配置没生效”按顺序查：

1. key、YAML 层级、prefix 是否一致；
2. 当前激活了哪些 Profile；
3. 是否有外部配置文件；
4. 环境变量是否正确转换；
5. 是否存在 `-D`、`--` 或 IDE 启动参数覆盖；
6. 看绑定异常最底层 cause；
7. 受控环境临时用 Actuator 辅助，验证后收回端点。

常见异常：

```text
Could not bind properties
BindValidationException
Could not resolve placeholder
```

## 四、查阅即可，不要求死背

- 完整 `PropertySource` 十几级优先级；
- `spring.config.location` 的 location group 细节；
- `spring.config.import` 与 `configtree:`；
- List / Map 的全部复杂合并规则；
- 自定义 Converter 和配置元数据格式。

需要时查阅 [Spring Boot 4.1 Externalized Configuration](https://docs.spring.io/spring-boot/4.1/reference/features/external-config.html)。
