# 第06章 · 死记硬背

> 标 ⭐ 是面试高频，标 ⚠️ 是容易踩的坑。

---

## 四类对象速查

| 类型 | 包 | 校验注解 | 出现在 Controller | 出现在 Service | 出现在 Repository |
|---|---|---|---|---|---|
| `XxxEntity` | `domain/entity` | ❌ | ❌ 禁止 | ✅ 内部 | ✅ |
| `CreateXxxRequest` | `domain/dto` | ✅ | ✅ 入参 | ✅ 接收 | ❌ 禁止 |
| `UpdateXxxRequest` | `domain/dto` | ✅ | ✅ 入参 | ✅ 接收 | ❌ 禁止 |
| `XxxVO` | `domain/vo` | ❌ | ✅ 返回 | ✅ 生产 | ❌ |
| `XxxQuery` | `domain/dto` | 可选 | ✅ 入参 | ✅ 接收 | ❌ |

---

## 转换规则 ⭐

```
客户端 JSON  →  反序列化  →  Request DTO
Request DTO  →  Service toEntity()  →  Entity
Entity       →  Repository save/update  →  Entity（含 id）
Entity       →  Service toVO()  →  VO
VO           →  序列化  →  客户端 JSON
```

**转换只在 Service 层做**，写成私有方法：

```java
private ProductVO toVO(ProductEntity e) {
    return new ProductVO(e.id(), e.name(), e.sku(),
                         e.price(), e.category(), e.createdAt());
}

private ProductEntity toEntity(CreateProductRequest r, LocalDateTime now) {
    return new ProductEntity(null, r.name(), r.sku(),
                             r.price(), r.category(), now, now);
}
```

## 命名约定

| 场景 | 命名 | 反例（不要用） |
|---|---|---|
| 创建入参 | `CreateProductRequest` | `ProductDTO`、`ProductForm` |
| 更新入参 | `UpdateProductRequest` | `ProductEditDTO` |
| 查询条件 | `ProductQuery` | `ProductFilter`、`SearchParam` |
| 详情响应 | `ProductVO` | `ProductInfo`、`ProductData` |
| 列表响应 | `ProductSummaryVO` | `ProductListItem` |
| 数据库映射 | `ProductEntity` | `Product`、`ProductDO` |

## 分层违规 TOP 5 ⚠️

1. **Entity 直接作为 Controller 返回值** → 暴露敏感字段，接口与数据库强耦合
2. **Entity 直接作为 Controller 入参** → mass assignment 漏洞（客户端能设置 id、createdAt）
3. **Request DTO 流进 Repository** → 分层倒置，Repository 依赖上层
4. **Entity 上加 `@JsonIgnore`** → 说明 Entity 已经在序列化链路里，根因是缺少 VO
5. **转换逻辑写在 Entity/VO 里** → 对象知道如何变成另一层的形态，违反单一职责

---

## Entity 不加这些 ⚠️

```java
// 这些注解不属于 Entity
@JsonIgnore               // Entity 不参与 JSON 序列化
@NotBlank                 // Entity 不是校验边界
@Column(nullable=false)   // M01 阶段暂无 JPA，M02 再加
```

---

## VO 不加这些 ⚠️

```java
// VO 是只出不进的对象，这些不属于它
@NotNull   // VO 不接受客户端输入，无需校验
setter     // VO 应该不可变，用 record
toEntity() // VO 不知道如何转换回 Entity
```

---

## 列表 vs 详情 VO ⭐

```
列表接口 → ProductSummaryVO（id, name, price, category）
详情接口 → ProductVO（id, name, sku, price, category, createdAt）
```

**不要让列表接口返回含大量 null 的详情对象**。额外的类不是成本，是清晰度。

---

## Query 对象 vs 多个 @RequestParam

```java
// ❌ 参数爆炸
@GetMapping
public Result<?> list(
    @RequestParam int page,
    @RequestParam int size,
    @RequestParam(required=false) String keyword,
    @RequestParam(required=false) String category,
    @RequestParam(required=false) String sortBy,
    @RequestParam(required=false) String sortDir) { ... }

// ✅ Query 封装
@GetMapping
public Result<?> list(ProductQuery query) { ... }
```

Spring MVC 可以直接将查询参数绑定到无注解的 POJO 或 `record`（需满足绑定条件）。

---

## 一句话总结

> 每一层的对象类型对应该层的职责边界：**入参在边界校验，实体在边界之内流转，出参在边界过滤**。转换集中在 Service，不外泄。
