### 任务三：引入 ProductQuery，支持分页和关键字过滤 ⭐

> - 性质：正式交付
> - 实现位置：`homework/delivered/product-service/src/main/java/com/study/mall/product/domain/dto/`
> - 级别：必做
> - 是否阻塞推进：是
> - 前置交付：任务二
> - 验证方式：`GET /api/v1/products?page=0&size=1&keyword=iPhone` 返回正确分页结果

新建 `ProductQuery`：

```java
public record ProductQuery(int page, int size, String keyword) {
    public ProductQuery {
        if (page < 0) page = 0;
        if (size <= 0) size = 20;
        // size 上限从 ProductConfig 读取（已有 pagination.maxSize 配置）
    }
}
```

新建通用分页响应类 `Page<T>`（放在 `common/result/`）：

```
items      List<T>   当前页数据
total      long      总记录数
page       int       当前页（从 0 开始）
size       int       每页大小
totalPages int       总页数
```

修改 `ProductService`：

- 新增 `list(ProductQuery query)` 方法，返回 `Page<ProductSummaryVO>`；
- 分页逻辑在 Service 里做（内存 List 截取），不在 Repository 里做；
- `keyword` 为空时返回全部；不为空时按 `name` 或 `category` 包含匹配（`String.contains`，大小写不敏感）；
- `size` 超过 `ProductConfig.pagination().maxSize()` 时使用最大值，不报错（静默截断，区别于第04章进阶任务的报错方案）；
- 原有 `findAll()` 保留（供内部使用），新增 `list()` 对外。

修改 `ProductController.list()`：

- 将多个 `@RequestParam` 替换为绑定 `ProductQuery` 对象；
- 研究 Spring MVC 如何将查询参数绑定到 `record`（提示：不需要 `@RequestBody`，也不是 `@RequestParam`，看 `@ModelAttribute` 或无注解直接绑定的行为）；
- 返回 `Result<Page<ProductSummaryVO>>`。

**验收标准：**

- `GET /api/v1/products` 返回第一页（默认 size=20）；
- `GET /api/v1/products?page=0&size=1` 返回第一条，`totalPages` 正确；
- `GET /api/v1/products?keyword=phone` 只返回 name 或 category 含 "phone"（大小写不敏感）的商品；
- 响应格式：`{"code":"SUCCESS","data":{"items":[...],"total":N,"page":0,"size":1,"totalPages":N},"message":"ok"}`。

### 任务五：端到端验证 ⭐

> - 性质：正式交付（验证记录）

> - 是否阻塞推进：是

```bash
# 准备数据：创建三条商品
POST /api/v1/products  {"name":"iPhone 16","sku":"PHONE-001","price":6999,"category":"手机"}
POST /api/v1/products  {"name":"MacBook Pro","sku":"LAPTOP-001","price":12999,"category":"笔记本"}
POST /api/v1/products  {"name":"iPhone 15","sku":"PHONE-002","price":5999,"category":"手机"}

# 1. 查询列表（无参数，默认分页）
GET /api/v1/products
# 预期：items 含 3 条，每条无 sku 字段，total=3

# 2. 分页
GET /api/v1/products?page=0&size=2
# 预期：items 2 条，total=3，totalPages=2

# 3. 第二页
GET /api/v1/products?page=1&size=2
# 预期：items 1 条，page=1

# 4. 关键字过滤

# 预期：返回 iPhone 16 和 iPhone 15（大小写不敏感），不含 MacBook

# 5. 详情接口（仍含 sku）

# 预期：响应含 sku 字段

# 6. 超出 size 上限
GET /api/v1/products?size=9999
# 预期：使用 maxSize 上限（100 或配置值），不报错，返回数据正常
```

在交付说明中填写每个请求的关键响应。

**验收标准：**

- 列表接口无 `sku` 字段；
- 详情接口有 `sku` 字段；
- 分页数学正确；
- 关键字过滤不区分大小写；
- 超出 size 上限时静默截断，不返回 400。

### 任务七：record 绑定原理研究

> - 性质：知识点实验
> - 实现位置：`homework/experimental/record-binding-lab/`（新建最小工程）
> - 级别：进阶
> - 是否阻塞推进：否

Spring MVC 将查询参数绑定到 `record` 时有特定要求。新建实验工程，研究并回答：

1. 直接使用无注解的 `record` 作为 Controller 参数，能否绑定成功？需要什么条件？

3. `record` 的紧凑构造器（compact constructor）在绑定时会不会被执行？用实验证明。
4. 如果 `record` 的某个字段在请求中未传，绑定结果是什么？

脚手架：创建包含一个 `@GetMapping` 和 `record` 参数的最小 Spring Boot 工程，通过 curl 验证绑定行为。
