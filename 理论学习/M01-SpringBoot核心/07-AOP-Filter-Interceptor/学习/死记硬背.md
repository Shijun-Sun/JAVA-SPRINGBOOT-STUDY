# 第07章 · 死记硬背

> 标 ⭐ 是面试高频，标 ⚠️ 是容易踩的坑。

---

## 三层落点速查 ⭐

| 维度 | Filter | Interceptor | AOP |
|---|---|---|---|
| 来自 | Servlet 规范 | Spring MVC | Spring AOP |
| 位置 | DispatcherServlet 之前 | Controller 前后 | 任意 Bean 方法前后 |
| 知道打到哪个方法 | ❌ | ✅ handler | ✅ 且拿参数/返回值 |
| 拿方法入参/返回值 | ❌ | ❌ | ✅ |
| 能切 Service/Repository | ❌ | ❌ | ✅ |
| 典型用途 | traceId、编码、跨域、限流 | 鉴权、访问日志、耗时 | 方法级耗时、审计、缓存、事务 |

---

## 执行顺序（背下来）⭐

```
Filter 前
 → Interceptor.preHandle
   → AOP @Around 前
     → Controller / Service
   → AOP @Around 后
 → Interceptor.postHandle
 → Interceptor.afterCompletion
Filter 后
```

外→内进入，内→外返回。**Filter 最外，Interceptor 居中，AOP 最内。**

---

## Interceptor 三方法 ⭐

| 方法 | 时机 | 抛异常时 | 用途 |
|---|---|---|---|
| `preHandle` | Controller 前 | 决定放行 | 鉴权、计时开始 |
| `postHandle` | 正常返回后 | ❌ 不执行 | 改 ModelAndView（少用） |
| `afterCompletion` | 请求结束 | ✅ 一定执行 | 记耗时、清理 |

**耗时/访问日志放 `afterCompletion`**，因为只有它异常时也执行。

---

## AOP 五种通知

| 注解 | 时机 |
|---|---|
| `@Before` | 方法前 |
| `@AfterReturning` | 正常返回后（拿返回值） |
| `@AfterThrowing` | 抛异常后（拿异常） |
| `@After` | 结束后（相当于 finally） |
| `@Around` | 包住方法，最强，必须 `proceed()` |

---

## traceId 标准写法 ⭐

```java
// 放 Filter（最外层），用 MDC
String traceId = req.getHeader("X-Trace-Id");
if (traceId == null || traceId.isBlank())
    traceId = UUID.randomUUID().toString().replace("-", "");
MDC.put("traceId", traceId);
resp.setHeader("X-Trace-Id", traceId);
try {
    chain.doFilter(req, resp);
} finally {
    MDC.remove("traceId");   // ⚠️ 必须清理
}
```

日志 pattern：`%X{traceId:-}` （取 MDC 值，无则空）。

**为什么放 Filter 不放 Interceptor/AOP**：Filter 最外，覆盖整条链路的日志；放里面会有一段日志没 traceId。

---

## TOP 坑 ⚠️

1. **MDC 用完不 remove** → 线程池复用，串味（下个请求打出上个的 traceId）
2. **耗时 start 存成 Interceptor 成员变量** → 单例多线程共享，并发算错。要用 `req.setAttribute`
3. **访问日志放 postHandle** → 异常请求不记录，最该看的日志没了。放 afterCompletion
4. **@Around 忘了 proceed()** → 目标方法根本不执行
5. **AOP 同类自调用** → 切面失效（没走代理），和 @Transactional 自调用失效同根因
6. **traceId 放 Interceptor** → Filter 层和映射阶段日志无 traceId，链路断裂

## Filter 注册

```java
// 推荐：能控顺序和路径
@Bean
FilterRegistrationBean<TraceIdFilter> traceIdFilter() {
    var reg = new FilterRegistrationBean<>(new TraceIdFilter());
    reg.addUrlPatterns("/*");
    reg.setOrder(Ordered.HIGHEST_PRECEDENCE);  // 越小越先
    return reg;
}
```

优先继承 `OncePerRequestFilter`，保证一次请求只执行一次。

---

## Interceptor 注册

```java
@Configuration
class WebMvcConfig implements WebMvcConfigurer {
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(accessLogInterceptor)
                .addPathPatterns("/api/**")
                .excludePathPatterns("/actuator/**");
    }
}
```

Interceptor 能按路径精确匹配，Filter 的 URL 匹配弱。

---

## Spring AOP 边界 ⚠️

- 只切 **Spring 管理的 Bean** 的方法
- 基于**动态代理** → 自调用、`new` 的对象、static 方法切不到
- 要切任意方法 → AspectJ 织入（本课不涉及）

---

## 一句话总结

> 每类横切关注点都有唯一最优落点：**traceId 在 Filter（最外全覆盖），访问日志/鉴权在 Interceptor（知道 handler、异常也记），方法级监控在 AOP（拿得到参数返回值）**。选错落点，要么信息拿不到，要么留死角，要么出并发 bug。
