# M02 · 关系型数据库 MySQL 与持久层

> 模块定位：**架构师的水位线基本由这一块决定**。M01 把工程骨架搭好了，但数据还躺在
> 内存的 `HashMap` 里——进程一停就全没了、多实例各存各的、没法查询统计。这个模块
> 要把数据真正**落到 MySQL**，并搞清楚"数据在磁盘上到底怎么存、索引为什么快、
> 事务和锁在并发下怎么表现、慢 SQL 怎么优化"。
>
> 前置：M01（product-service 骨架，内存存储、分层、统一响应、测试安全网）
> 预计周期：2.5 ~ 3 周（本模块最重，慢一点没关系）

---

## 一、模块目标（学完要能做到）

原理层面：
- 说清 InnoDB 一行数据从"磁盘上的页"到"内存里的对象"的完整路径
- 说清 B+ 树为什么适合做数据库索引，聚簇索引和二级索引差在哪、什么是回表
- 说清联合索引的最左前缀，能判断一条 SQL 会不会走索引、为什么失效
- 说清四种事务隔离级别各自防住了什么、MVCC 是怎么实现"读不加锁"的
- 说清行锁、间隙锁、Next-Key Lock 与死锁的成因和排查

工程层面：
- 会设计电商核心域的库表（商品 SPU/SKU、分类、库存），字段类型和索引选得出理由
- 会用 `EXPLAIN` 读执行计划，定位并优化一条真实的慢 SQL
- 会用 Flyway 做版本化的 schema 迁移，而不是手动改库
- 把 `product-service` 的内存存储换成 MySQL（MyBatis-Plus 为主，JPA 作对照），测试安全网仍然全绿
- 理解连接池 HikariCP 的关键参数，能解释"连接数不是越大越好"

## 五、环境准备

本模块需要一个可连接的 MySQL 8.4——**已用 Docker 起好**：

| 项 | 值 |
|----|----|
| 容器 | `mysql84`（`mysql:8.4`，`utf8mb4` / `utf8mb4_0900_ai_ci`） |
| 连接 | `localhost:3306`，`root` / `root123456`，库 `mall` |
| 数据卷 | `mysql84-data`（重启不丢数据） |
| 已建表 | 商品域 `category` / `spu` / `sku`（含 03 章补的查询索引） |

- 连接、灌数据、重置的完整操作看训练营脚手架：`homework/experimental/sql-practice-lab/README.md`；
- 客户端可以用 IDEA 自带的 Database 面板、DBeaver 或命令行 `mysql`（图形界面看结果最直观）；
- 容器丢了用脚手架 README 末尾的 `docker run` 命令重建；Compose 编排到第 10 章落地时给出。

> 前几章（01~06）以**原理 + SQL 手写验证**为主，一个能连的 MySQL 就够；
> 到第 08 章接持久层框架、第 10 章落地改造时，才需要把连接配进 `product-service`。
