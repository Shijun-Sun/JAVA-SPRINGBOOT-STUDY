01 章你把 `category` / `spu` / `sku` 表设计出来了，但**只建了主键和唯一键**，普通查询索引按约定留到了本章。02 章你搞清了二级索引、回表、覆盖的原理。现在要把这些用起来：**面向真实查询，为商品域设计出普通查询索引**，让详情页、列表页、分类页的查询从"全表扫描"变成"走索引"。

```sql
-- Q3 商品详情：某 SPU 下的所有 SKU
```

### 任务三：最左前缀判断题

> - 性质：知识点实验（理解巩固）
> - 实现位置：`homework/experimental/index-design-lab/最左前缀分析.md`（自建目录，纯文档）
> - 级别：必做
> - 是否阻塞推进：否
> - 前置交付：无（读完讲义即可）
> - 验证方式：每条判断正确且给出理由

设 `spu` 上有联合索引 `idx (category_id, status, created_at)`。对下面每条查询，判断：**用到索引的哪几列？要不要回表？会不会用到索引排序（还是 filesort）？为什么？**

```sql
-- A
SELECT id FROM spu WHERE category_id = 3;
-- B
SELECT id FROM spu WHERE status = 1;
-- C
SELECT id FROM spu WHERE category_id = 3 AND status = 1 ORDER BY created_at DESC;
-- D
SELECT id, name FROM spu WHERE category_id = 3 AND status = 1;
-- E
SELECT id FROM spu WHERE category_id = 3 AND created_at > '2026-01-01';
-- F
SELECT id FROM spu WHERE category_id > 3 AND status = 1;
```

**验收标准（要点）：**

- A：用到 `category_id`；查 `id`（主键在二级索引叶子里）→ **不回表（覆盖）**；
- B：缺最左列 `category_id` → **用不上该索引**；
- C：用到 `category_id, status` 定位，`created_at` 在该段有序 → 排序**走索引不 filesort**；查 `id` 覆盖不回表；
- D：用到 `category_id, status`；要 `name` 不在索引 → **回表**；
- E：用到 `category_id`；`created_at` 是范围能用，但注意中间的 `status` 未给——说清 `created_at` 能不能接着用（提示：缺了 `status`，`created_at` 用不上索引定位，只能 ICP 过滤 / 回表后过滤）；
- F：`category_id > 3` 是范围 → 其后的 `status` **停用**，只用到 `category_id`。

> 每条都要写"为什么"，不能只写结论。E、F 是最容易错的两条，重点想清楚。

下面每条 SQL 都有"索引失效"问题。**指出失效根因，并改写成能走索引的形式**（假设相关列都有合适索引）：


## 附录 · EXPLAIN 关键列速读（面向 SQL 基础薄弱）

> 观察线要看 `EXPLAIN`。本附录只教本章要用的几列，系统解读在第 04 章。

`EXPLAIN` 放在 `SELECT` 前，MySQL **不真跑查询**，只告诉你它打算怎么执行：

```sql
EXPLAIN SELECT id FROM spu WHERE category_id = 3 AND status = 1;
```

本章重点看四列：

- **`type`**（访问类型，好→坏）：`const`（主键/唯一等值）> `ref`（普通索引等值）> `range`（范围）> `index`（扫整个索引）> **`ALL`（全表扫描，最差 ⚠️）**。
- **`key`**：实际用上的索引名。`NULL` = 没走索引。
- **`key_len`**：用到了联合索引的**前多少字节**——能侧面看出"最左前缀用到了第几列"（越长用到的列越多）。
- **`Extra`**：
  - **`Using index`** = 覆盖索引，**不回表**（好）；
  - **`Using index condition`** = 用了 ICP，减少回表；
  - **`Using where`** = 存储层之上还要过滤；
  - **`Using filesort`** = 需要额外排序（`ORDER BY` 没走上索引 ⚠️）；
  - **`Using temporary`** = 用了临时表（常见于 `GROUP BY`，代价高 ⚠️）。

> 本章能区分：`ref`/`range`（走了索引）vs `ALL`（全表扫）；`Using index`（不回表）vs 没有它（回表）；有没有 `Using filesort`。
