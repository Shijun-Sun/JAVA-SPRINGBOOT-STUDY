# 大型电商系统 · 后端架构能力训练路线

> 终极目标：具备**大型电商项目的架构能力** —— 每个环节的原理都讲得清、每个环节的操作都做得出。
> Spring Boot 只是其中一个模块，不是主题。
>
> 现状基线（2026-08）：Java 基础语法已完成；多年前端经验；早期 Java 7/8 + Spring MVC 经验。

---

## 一、这套训练的组织方式

整个学习拆成两条并行的线：

| 目录 | 作用 | 说明 |
|------|------|------|
| `理论学习/` | 原理 + 最小可运行验证 | 按模块推进，每模块：**知识讲解 → 作业实操 → 我 review** |
| `项目实战/` | 真实开源电商项目 | 读源码、改需求、最终部署成"生产环境" |

两条线的关系：**理论学习模块 M(n) 学完，立刻去实战项目里找对应的真实实现来对照。**
理论负责"为什么这么设计"，实战负责"大型项目实际长什么样"。

### M01 Spring Boot 核心与工程规范
搞清楚"框架帮我做了什么"，建立一个能长期演进的工程骨架。
自动配置与启动流程 / IoC 与 Bean 生命周期 / 配置体系与 Profile / REST API 与参数校验 /
统一响应与全局异常 / 分层边界（Entity·DTO·VO）/ AOP 与 traceId / 单元与集成测试 / 打包与外部化配置
**产出**：`product-service` 商品服务骨架（内存存储），带统一响应、校验、异常处理、链路日志、MockMvc 测试。

### M02 关系型数据库 MySQL 与持久层
架构师的水位线基本由这块决定。
电商数据建模（商品·SKU·订单·库存·用户）/ InnoDB 存储结构与 B+ 树 / 索引设计与最左前缀 /
EXPLAIN 与慢查询优化 / 事务隔离级别、MVCC、间隙锁与死锁 / 连接池 HikariCP /
持久层选型（MyBatis-Plus vs Spring Data JPA）/ Flyway 版本化迁移 / 主从复制与读写分离 / 分库分表入门
**产出**：把 M01 的内存存储换成 MySQL，完成一次真实的索引与慢 SQL 优化，Flyway 管理 schema。

### M03 Redis 与缓存架构
数据结构与适用场景 / 缓存读写模式（Cache Aside / 穿透·击穿·雪崩）/ 缓存与 DB 一致性方案 /
过期与内存淘汰 / 持久化 RDB·AOF / 分布式锁（SETNX 的坑 → Redisson → Lua）/
Redis 扣减库存 / 限流（令牌桶 + Lua）/ 主从·哨兵·Cluster
**产出**：商品详情多级缓存 + 一致性方案 + 基于 Redis 的库存扣减与接口限流。

### M04 认证授权与接口安全
Spring Security 6/7 过滤器链 / JWT 与 Refresh Token / OAuth2 与 OIDC / RBAC 权限模型 /
多端登录与 Token 吊销 / 网关鉴权与服务间信任 / 加密存储、防重放、防刷、幂等 Token
**产出**：会员登录 + 商品后台 RBAC 权限控制。

### M05 Nginx、反向代理与负载均衡
Nginx 进程模型与事件驱动 / location 匹配规则 / 反向代理与 upstream /
负载均衡算法（轮询·权重·least_conn·ip_hash·一致性哈希）/ 健康检查与故障转移 /
动静分离与静态资源缓存 / HTTPS 与 HTTP/2 / gzip·brotli / limit_req·limit_conn 限流 /
灰度发布与蓝绿 / 日志与真实 IP 透传 / 与 LVS·SLB·K8s Ingress 的分层关系
**产出**：Nginx 反代 3 个本机应用实例，压测验证负载均衡与故障转移，
配 HTTPS（mkcert 本地 CA）与限流，做一次灰度发布。
多实例会当场暴露单实例永远发现不了的问题：本地缓存不一致、Session 存内存、定时任务重复执行。

### M06 消息队列与异步 / 最终一致性
MQ 选型（RocketMQ vs Kafka vs RabbitMQ）/ 削峰填谷与解耦 / 顺序、重复、堆积 /
生产端可靠投递与事务消息 / 消费幂等与死信 / 延迟消息（订单超时关单）/
本地消息表 / 最终一致性与对账补偿
**产出**：下单异步化（扣库存·发券·通知）+ 订单超时自动关单 + 幂等消费。

### M07 Elasticsearch 与商品搜索
倒排索引原理 / 分词与中文 IK / mapping 设计 / DSL 查询与聚合 /
相关性打分与业务排序干预 / 商品数据同步（双写 vs Canal binlog）/ 深分页与 search_after
**产出**：商品搜索 + 筛选聚合 + 排序，MySQL → ES 增量同步。

### M08 分布式与微服务
单体模块化 vs 微服务的取舍（先讲什么时候**不要**拆）/ 服务拆分边界与 DDD /
注册配置中心 Nacos / 网关 Spring Cloud Gateway / 熔断降级限流 Sentinel /
服务调用 OpenFeign / 分布式事务（Seata AT·TCC·Saga·可靠消息）/
分布式 ID（雪花算法）/ 分布式锁 / 分布式会话
**产出**：把单体拆成 网关 + 商品 + 订单 + 会员，跑通一次跨服务分布式事务。

### M09 容器化与部署
Docker 镜像分层与多阶段构建 / Compose 编排本地全套中间件 /
K8s 核心对象与探针、滚动更新、HPA / 配置与密钥管理 / CI/CD 流水线 / 生产发布与回滚预案
**产出**：整套系统容器化，一键起环境；本机 k3d 集群跑完整部署，作为"模拟生产环境"。
CI/CD 的 workflow 代码照写照 review，不接真实算力（原因见 `项目实战/环境/01-环境清单与部署拓扑.md`）。

### M10 可观测性、压测与性能调优
Actuator + Micrometer + Prometheus + Grafana / OpenTelemetry 全链路追踪 /
结构化日志与 ELK / 告警设计 / JMeter·wrk 压测方法论 /
JVM 内存模型与 GC 调优、OOM 与线程 dump 分析 / 线程池与虚拟线程 / 全链路瓶颈定位
**产出**：监控大盘 + 链路追踪，一次完整压测报告（找到瓶颈 → 优化 → 数据对比）。

### M11 电商高并发专题 + 架构设计答辩
秒杀系统完整设计（限流·预热·库存·异步下单·防超卖·防刷）/ 订单状态机 /
库存模型（预占·锁定·回滚）/ 支付与回调幂等、对账 / 优惠券与价格计算 /
高可用与容灾（多活·降级·熔断预案）/ 容量评估与成本
**产出**：面对"日订单 100 万的电商系统怎么设计"能画出完整架构图并逐层答辩。

## 三、每个模块的推进节奏

固定五步，和你学 Java 语法时一致：

1. **我出讲义** —— 模块目录下 `NN-主题.md`，原理讲清楚，配最小示例
2. **你读 + 提问** —— 不懂就问，问题会被记到 `笔记/学习笔记.md`
3. **你做作业** —— `作业/` 目录下有题目和验收标准，代码/配置自己写
4. **我 review** —— 按固定格式给结论、错误清单、改进方向（默认不直接给答案）
5. **模块验收** —— 通过"验收清单"里的口头考核 + 实操产出，才进下一模块

Review 口令（沿用旧习惯）：
`只指出错误，不直接给答案` / `先解释问题，再给改进建议` / `直接给标准答案` / `按初学者角度讲解`

## 四、技术栈基线（2026-08 核实）

```
JDK            Java 25 LTS（当前本机 17，建议升级；虚拟线程需要 21+）
框架           Spring Boot 4.0.x（2025-11 GA，基于 Spring Framework 7 / Jakarta EE 11）
构建           Maven 3.9.11 ✅ 已装
数据库         MySQL 8.4 LTS（容器）
缓存           Redis 7.x（容器）
持久层         MyBatis-Plus 为主，Spring Data JPA 作对照
迁移           Flyway
搜索           Elasticsearch 8.x
消息队列       RocketMQ（主）/ Kafka（对照）
安全           Spring Security + JWT / OAuth2
接入层         Nginx 1.27+
微服务         Spring Cloud + Spring Cloud Alibaba（Nacos / Sentinel / Seata）
可观测         Actuator + Micrometer + Prometheus + Grafana + OpenTelemetry
部署           Docker 29 ✅ + Compose v5 ✅ + Kubernetes
```

关于版本的两点说明（重要，别踩坑）：

- **Spring Boot 3.5 的开源版本已于 2026-06-30 停止维护**，所以主线走 **Boot 4.0**。
- 但国内生态（MyBatis-Plus、Spring Cloud Alibaba 等）对 Boot 4 的适配进度不一，**每个模块开始前我会先核实当时的版本兼容矩阵**，卡住就退回 Boot 3.5 做对照，并把差异讲清楚。版本迁移本身就是架构师的必修课，不回避。
- 实战项目 `mall` 目前是 Boot 3.2，和我们的主线有版本差 —— 这不是坏事，正好当作**版本迁移与差异分析**的真实素材。
